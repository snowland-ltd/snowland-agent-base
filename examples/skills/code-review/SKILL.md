## 评审顺序

按下列顺序过一遍，避免遗漏：

1. **正确性**：逻辑是否符合预期，边界条件是否处理。
2. **健壮性**：异常路径、空值、并发与资源释放。
3. **安全性**：注入风险、敏感信息泄露、权限校验。
4. **性能**：不必要的循环嵌套、重复 IO、N+1 查询。
5. **可维护性**：命名、重复代码、注释是否说明「为什么」。

## 输出格式

按严重程度分级：

- **阻塞**：必须修复，否则功能不可用或存在安全风险。
- **建议**：应当修复，影响质量或性能。
- **可选**：风格与可读性改进。

每条需给出：位置、问题、原因、建议改法。

## 原则

- 只报告确有把握的问题，避免主观偏好造成噪音。
- 区分「事实」与「推测」，推测需明确标注。
- 不改动与本次变更无关的代码。
